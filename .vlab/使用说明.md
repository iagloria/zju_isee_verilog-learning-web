# Verilog 闯关训练 —— 使用说明

这是一个**本地运行的 LeetCode 式练习网站**，专门针对你这四份复习资料（教材 1–12 章 + FSM 专题）出的手写代码题。
判题不是“假判题”：它会在你电脑上**真的调用 Icarus Verilog 编译你的代码、跑测试台**，逐条告诉你哪组输入错了、错在哪。

---

## 一、怎么打开

**双击复习文件夹（或 `.vlab` 文件夹）里的 `启动训练.bat`。**

- 黑色窗口会显示启动进度，**几秒后自动打开浏览器**。
- 如果浏览器没自动打开，手动访问窗口里显示的地址（默认 `http://127.0.0.1:7826/`）。
- **窗口可以直接关掉**，服务在后台继续运行，不影响使用。

**要停止服务**：双击 `停止训练.bat`（或重启电脑）。

> **地址可能不是 7826**：如果 7826 被别的程序（比如以前没关掉的旧版本）占着，
> 启动器会自动改用 7827、7828……，并在窗口中明确告诉你用的是哪个端口。
> 请看窗口里那一行「地址：http://127.0.0.1:XXXX/」。

> 说明：第一次启动会自动预编译测试台（约 5 秒），之后每次判题都在 0.5–1 秒内出结果。

### 如果启动失败

窗口不会一闪而过，而是停住并显示**真实错误信息**（以及日志文件路径）。
把那段文字发给我即可定位。

日志位置：`.vlab\data\logs\server.log` 和 `server.err.log`。

## 二、界面长什么样

```
┌───────────┬───────────────────────┬──────────────────────────────┐
│ 题目列表   │  题目描述              │  代码编辑器                    │
│ (按章节)   │  （含示例、要求）        │   [文件标签] 解释 重置 保存 [▶运行] │
│ ✓ 已通过   │                       ├──────────────────────────────┤
│ ● 未通过   │                       │  运行结果 / 运行日志 / 波形 / 参考答案 │
└───────────┴───────────────────────┴──────────────────────────────┘
```

- **左侧**：所有题目按章节分组（第 2–3 章 … 第 12 章 + FSM 专题）。绿点是已通过，黄点是做错了，灰点还没做。
- **中间**：题目描述、要求、以及「手写练习区」（`✍️` 那块大文本框，专为**模拟卷面**准备的，可以先把答案默写在这里）。
- **右侧上方**：CodeMirror 编辑器，带 Verilog 语法高亮、自动缩进、括号匹配。
- **右侧下方**四个标签页：
  - **运行结果**：通过/失败判决、每个测试点、错误原因、静态检查提示
  - **运行日志**：iverilog 编译输出 + 仿真输出原文（教你看 `[CHECK]F ...`）
  - **波形**：时序题会把关键信号按拍画出波形
  - **参考答案**：答案 + 考点提醒（建议先自己做）

## 三、按钮和快捷键

| 按钮 / 快捷键 | 作用 |
|---|---|
| `▶ 运行` / `Ctrl+Enter` | 编译 + 仿真 + 判题（真跑 Icarus Verilog） |
| `解释一下` / `Ctrl+E` | 只做静态检查（秒回）：锁存器、reg/wire、位宽、敏感表、FSM default、UDP 格式… |
| `重置` | 恢复成题目初始代码 |
| `保存` / `Ctrl+S` | 把代码存到 `.vlab\data\answers\` |

| `📝 生成手写模拟卷` | 新窗口打开一份“卷子”（题目 + 作答区），可直接 Ctrl+P 打印 |
| `📄 导出 Word 模拟卷` | 生成 `Verilog手写模拟卷.docx` 和 `Verilog参考答案.docx`，在 Word 里批注、打印 |
| `📂 打开答案存档` | 打开你保存过的答案文件夹 |

## 四、题目类型

共 **45 道**（33 道编程/找错题 + 12 道概念选择题，选择题会即时判分并给解析）。

| 类型 | 说明 | 例子 |
|---|---|---|
| **手写代码** | 从功能描述开始写整个模块（考试大题） | 三段式 FSM、模 10 计数器、售货机 |
| **补全代码** | 主框架已给，补关键几行 | 敏感表怎么写、门级 MUX |
| **找错改错** | 代码能编译但结果不对（或写法有隐患），修好它 | 阻塞/非阻塞、进位丢失、锁存器 |
| **写 Testbench** | 自己写 TB 验证给定的 DUT | 时钟+复位+5 组激励、`$readmemh` 文件输入 |
| **概念选择** | 单选/多选，选项打乱前先自己判断 | Moore/Mealy、`==`/`===`、task/function |

## 五、判题是怎么判的（为什么可信）

每道题都配了**专门的测试台**（你看不到，也不参与你手写的评分），例如：

- 组合逻辑题（MUX、编码器、ALU…）：**穷举所有输入**（比如 8 位优先编码器跑 256 组）。
- 时序题（寄存器、计数器、FSM）：按题目时序要求逐拍比对。
- Testbench 题：把你的 TB 和“参考 TB + 真实 DUT”放进同一个仿真里跑，检查你的 TB **是否真的把每组数据打到了 DUT 上**、有没有 `$finish`。

所以：
- **通过** = 功能真的对（不只是“看起来对”）。
- **静态检查**（「解释一下」）还会模拟老师批卷的扣分点：锁存器、`reg`/`wire` 用错、位宽、敏感表、FSM 缺 default 等。

> 这 33 道编程题的**标准答案**我都用真实仿真器跑过一遍，全部通过（见第八节）。

## 六、练习建议（贴合考试）

1. **先手写，再上机**：打开题目，先在中间「✍️ 手写练习区」默写，再复制到编辑器运行验证。考试是手写，这一步比“直接敲键盘”更接近实战。
2. **顺序建议**：基础操作（第 3–4 章）→ 门级/数据流（5–6）→ 行为级组合与锁存器（7 前半）→ 时序逻辑（7 后半）→ **FSM 专题**（最重要）→ Testbench（9）→ UDP（12）。
3. **错了别急着看答案**：看「运行结果」里哪一组失败了，猜是哪个信号/哪个时刻不对；实在不行看「运行日志」里的 `[CHECK]F` 行。
4. **考前用「生成手写模拟卷」**：它会把**你还没通过**的题优先选出来组成一份卷子，打印出来掐时间做完，再回来上机验证。
5. **对照答案前先看「参考答案」里的“关键点 / 考场提醒”**，那些是最容易丢分的地方。

## 七、文件夹里都有什么

```
.vlab\
├─ 启动训练.bat          ← 双击这个
├─ launch.js           启动逻辑
├─ server\               服务端（判题、静态检查、出卷）
│   ├─ app.js            本地 HTTP 服务（只监听 127.0.0.1）
│   ├─ cli.js            判题执行器（编译→仿真→解析）
│   ├─ judge.js          题库 + 判题流程
│   ├─ lint.js           静态检查规则
│   ├─ tbgrade.js        Testbench 题评分
│   ├─ exam.js / docxmaker.js  出卷
│   └─ prebuild.js       预编译测试台
├─ web\                  前端（HTML/CSS/JS + CodeMirror）
├─ data\
│   ├─ problems\         题库（每章一个 .js 文件，可自己加题）
│   ├─ tests\            各题的测试台
│   ├─ progress\         ★ 你的进度（做题记录 + 代码）
│   ├─ answers\          ★ 你保存的答案
│   └─ exams\            ★ 生成的 Word 模拟卷 / 答案册
├─ tools\icarus\         Icarus Verilog 14（便携版，不用安装）
└─ tools\备份.bat / 清理.bat
```

带 ★ 的是你自己的数据，**备份这个文件夹就够了**。

## 八、质量说明（我做过的验证）

- 33 道编程题的**官方答案**：全部用 Icarus Verilog 真实编译 + 仿真，**33/33 通过**。
- 端到端接口测试 9 项 + 浏览器流程 13 项：全部通过（含“错误答案必须被判错”的反例）。
- 每道题的测试台都复用了“参考实现 + 穷举/逐拍比对”，而不是只看有没有语法错误。

### 已知限制（重要，请读一下）

1. **Mealy 组合输出的“同一时刻”问题**：标准 Verilog 里，组合输出的变化和时钟沿可能在同一个仿真时刻发生；不同仿真器对“谁先处理”的规则不完全一致。**Icarus Verilog 对“在上升沿后 1ns 内变化的组合输出”会短暂保留旧值**，导致有些纯组合 Mealy 写法在测试里“看起来没输出”。
   - 所以本项目的 FSM 题统一要求/鼓励用**寄存器输出**（三段式最后一级 `found <= (state==S3) && din;`），这也是工程上更推荐的写法（无毛刺、宽度固定）。
   - 如果你在别处见到“纯组合 Mealy 判题总是不对”，原因基本就在这里，不是你的代码错了。
2. 判题器是 **Icarus Verilog 14**，支持 IEEE-1364-2005 + 一部分 SystemVerilog。Vivado 的 `always_ff`、`logic` 等 SystemVerilog 写法**不完全支持**；本课程只用 Verilog-2001 子集，所以不影响。
3. 题库和测试台我都核对过，但如果你发现某题“正确答案被判错”，**很可能是我测试台的期望值写错了**——题型和判题逻辑是通用的，欢迎告诉我题号。

### 关于“偶尔一次运行失败”

判题流程是“启动后台子进程 → 编译 → 仿真 → 读结果”。在这台电脑上我连续跑了 **125 次判题，全部成功**；但极端情况下（杀毒软件正在扫描刚生成的临时文件、系统负载很高），后台进程可能在启动瞬间失败，页面会提示：

> 判题服务出错：判题子进程没有返回结果……

**遇到这个提示，直接再点一次「▶ 运行」即可，不需要改代码。** 如果连续多次都这样，把 `.vlab\data\runs\_bridge\` 里的文件发给我排查。

### 如果看到 “Error opening temporary file … Please check TMP or TMPDIR”

**这不是你的代码错**，是编译器无法在 Windows 临时目录里创建临时文件
（常见的真实原因：用户 Temp 目录权限异常、被安全软件锁住、磁盘空间不足）。

本项目已经规避了这个问题：所有编译/仿真子进程都会把 `TMP`/`TEMP`/`TMPDIR`
强制指向 **`.vlab\data\tmp`**（项目内、确定可写）。

- 如果你仍看到这个报错，请检查 `.vlab\data\tmp` 是否可以写入、磁盘是否已满。
- 启动器启动时也会自检该目录，不可写时会打印 `⚠ 无法写入临时目录`。

## 九、想加题 / 改题

题库在 `.vlab\data\problems\` 下，每题是一个对象，例如：

```js
{
  id: 'my_p01',
  title: '4 位二进制转格雷码',
  type: 'write',
  difficulty: 2,
  tags: ['组合逻辑'],
  brief: '一行描述',
  desc: `题目描述（支持 Markdown）`,
  files: [{ name: 'bin2gray.v', content: `module bin2gray (...);\n  // TODO\nendmodule\n` }],
  tests: [{ tb: 'bin2gray' }],        // 对应 data/tests/<章节>/tb_bin2gray.v
  solution: `module bin2gray (...); ... endmodule\n`,
}
```

加完后**重启服务**（关掉黑窗口再双击 `启动训练.bat`）。

## 十、常见问题

**Q：双击 bat 没反应 / 闪一下就关？**
A：看看是不是被杀毒软件拦了；或者手动在该文件夹打开命令行，运行 `D:\node.js\node.exe server\app.js --open`（port 7826）。

**Q：浏览器打不开 127.0.0.1:7826？**
A：可能端口被占用或服务没起来。关掉黑窗口重新双击 `启动训练.bat`；若提示端口被占用，说明已经有一个在跑了，直接访问地址即可。

**Q：我想用 Vivado 的 xsim 验证自己的写法？**
A：可以用，但没必要——这里的判题用 Icarus，结果可复现、启动快（0.5 秒 vs Vivado 十几秒）。如果你要跑 Vivado，把 `.vlab\data\tests\` 里对应的测试台和自己的实现一起在 Vivado 里仿真即可。

**Q：进度会丢吗？**
A：进度存在浏览器 localStorage 和 `.vlab\data\progress\` 双份，清浏览器缓存也不怕。换电脑把 `.vlab` 整个文件夹拷走即可。
